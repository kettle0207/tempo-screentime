# Tempo スクリーンタイム

Windows 11 x64 用の個人向けスクリーンタイム。操作中のアプリの使用時間を自動で記録し、日本語のダッシュボードで振り返れます。アカウントや有料 API は不要です。

## 使い始める

1. GitHub の Releases ページから最新の `Tempo-Setup-x64.exe` をダウンロードして実行し、インストール先を選びます。通常は管理者権限は不要です。インストーラーは Authenticode 署名をしていないため、Windows の SmartScreen が確認を表示する場合があります。2 回目以降の更新は、アプリ内の「アップデートを確認」から行えます。
2. 完了画面で Tempo を起動します。初回起動から自動で計測され、次回以降は Windows へのサインイン時に常駐します。
3. 右上の「×」で画面を閉じても記録は続きます。スタートメニューの「Tempo」またはトレイアイコンのダブルクリックで画面を開けます。一時停止と終了はトレイアイコンの右クリックから選べます。

画面表示には Windows 11 の .NET Framework 4.8 以降と Microsoft Edge WebView2 Runtime が必要です。通常の Windows 11 には両方が含まれます。Runtime がない場合もトレイでの記録は動作します。インストーラーには開発環境や Runtime のネットワークインストーラーを含めていません。インストーラーは Authenticode のコード署名をしていませんが、アプリ内更新で取得するファイルは Tempo 独自の署名で検証します（後述）。

ZIP 配布版はフォルダーごと展開して `ScreenTime.exe` を起動します。同梱の DLL とフォルダーが必要です。展開後に移動した場合は、移動先で起動し、サイト計測を使う場合は拡張機能のフォルダーを選び直してください。

## 使用時間を見る

- **概要** では、いちばん上に期間の合計使用時間を大きく表示し、その下に前の期間との差を小さく示します。週・月・年では 1 日平均も表示します。グラフはカテゴリ別の積み上げ棒で、下の凡例にカテゴリごとの合計を並べます。続けて、よく使われたアプリ（とサイト）をアイコン・名前・時間の揃ったリストで表示します。グラフにポインターを合わせると、その時間帯の合計を確認できます。週・月のグラフで日を押すと、その日の表示に切り替わります。
- **日・週・月・年** で集計単位を切り替えます。日付をクリックして履歴に移動できます。「週」は月曜始まりです。比較は前の暦日・暦週・暦月・暦年の全期間が基準です。
- **アプリ・Webサイト** ではランキングを検索できます。鉛筆アイコンからカテゴリを変更すると、過去の履歴にも反映されます。「自動分類」で元に戻せます。
- **設定** ではライト・ダーク・Windows 連動のテーマ、自動起動、記録の一時停止、離席判定までの時間を変更できます。「ソフトウェアアップデート」に現在のバージョンを表示します。

## アップデート

1. 「設定」→「ソフトウェアアップデート」の「アップデートを確認」を押します。確認は押したときだけ行います。定期的な確認や、更新専用の常駐プロセスはありません。
2. 新しい版があれば、バージョン番号と変更内容を表示します。「ダウンロードして更新」を押すと、インストーラーを取得して検証します。
3. 検証に通ると、未保存の記録を保存してから Tempo を終了し、上書き更新します。更新が終わると Tempo が自動で再起動し、履歴・手動カテゴリ・設定を引き継いで記録を再開します。

- 通信先は GitHub Releases の更新情報（`tempo-update.txt`）とインストーラーだけです。送るのは汎用の User-Agent（`Tempo-Updater`）だけで、使用履歴・アプリ名・ドメイン・端末識別子・Cookie は送りません。ダッシュボード画面（WebView2）自体は、従来どおり外部へ通信できません。更新の通信は、画面プロセスの C# 側だけが行います。
- 更新情報は、アプリに埋め込んだ公開鍵で RSA-PSS 署名を検証します。インストーラーは、署名済みのサイズと SHA-256 が一致した場合だけ実行します。署名不一致・破損・通信切断・中止のときは、ダウンロードしたファイルを削除し、現在の版をそのまま使い続けます。
- 古い版への入れ替え（ダウングレード）は提示しません。ZIP 版はアプリ内更新の対象外です。
- 1.1 以前からは、1.2 のインストーラーを一度実行してください。履歴と設定はそのまま引き継がれます。リリース手順は [RELEASE.md](RELEASE.md) にあります。

## Chrome・Edge のサイト計測

1. Tempo の「設定」から「拡張機能フォルダーを開く」を選びます。ZIP 版ではこの操作で連携先も登録されます。
2. Chrome の `chrome://extensions` または Edge の `edge://extensions` を開き、「デベロッパー モード」を有効にします。「展開して読み込み」または「パッケージ化されていない拡張機能を読み込む」で、手順 1 の `Extension` フォルダーを選びます。利用するブラウザ・プロファイルごとに設定してください。
3. 通常のウィンドウで HTTP または HTTPS のページを操作すると、ドメインの記録が始まります。プライベートタブ、内部ページ、ローカルファイルは対象外です。拡張機能を追加できない管理端末や他のブラウザでは、ブラウザアプリの使用時間を表示します。

サイト時間はブラウザの使用時間の内数です。カテゴリはサイトへの手動指定、アプリへの手動指定、ドメインの自動分類、アプリの自動分類の順に決まります。アプリランキングにはブラウザ全体が表示されるため、ブラウザで動画を見ると、アプリ側にはブラウザ、カテゴリの内訳には動画として現れます。

## 計測とプライバシー

- 前面アプリが切り替わると、Windows の `EVENT_SYSTEM_FOREGROUND` 通知の時刻で区間を区切ります。フックは `WINEVENT_OUTOFCONTEXT` を使います。ゲームへの DLL 注入、ドライバー、管理者権限、プロセスメモリの読み取りは必要ありません。通知を登録できない場合だけ 2 秒間隔で前面を確認します。
- 操作中のタイマーは次の離席判定期限と最長 60 秒の保存期限に合わせます。離席中は 3 秒ごとに Windows の最終入力時刻を確認し、観測できた入力時刻から記録を再開します。この間に複数回入力した場合は、直近の入力までの短い区間を取り逃す場合があります。一時停止・ロック・サスペンド時には前面通知を解除し、保存済みならタイマーも停止します。
- 最終入力から設定時間（1・3・5・30 分、1 時間から選択。初期値 1 分）を過ぎた部分を除きます。30 分や 1 時間にすると、動画や読書など操作のない時間も長く記録されます。動画を流し続けたり、入力なしで読書したりする時間も同じ扱いです。ゲームパッドだけの操作は Windows の最終入力時刻に反映されず、離席と判定される場合があります。前面アプリのキーボード入力内容やウィンドウタイトル、画面画像は取得しません。
- ロック・セッション切断・サスペンドの通知で計測を区切ります。入力デスクトップを確認し、長い観測の途切れや時計の不連続をまたいで加算しません。
- 履歴は記録時のローカル日付・時刻で集計し、アプリの実行ファイル識別子、表示名、アイコン、カテゴリ、ドメイン、使用時間を SQLite に保存します。URL のパス・検索語・タブタイトルは保存しません。
- 標準の履歴ファイルは `%LOCALAPPDATA%\Tempo\ScreenTime\history.sqlite3` です。同じ日・時間帯・アプリ・サイトの時間をメモリで合算し、通常は最長約 60 秒で 1 トランザクションにまとめて書き込み、画面更新・一時停止・通常終了時にも保存します。強制終了時は未保存分が失われる場合があります。
- 拡張機能はドメインの変化だけを Native Messaging で通知します。連携ホストは同一セッション内のローカル専用名前付きパイプで本体に渡します。対象タブがなくなると、約 30 秒後にホストを解放します。ダッシュボードは EXE 内に同梱し、WebView2 へアプリ内から応答します。履歴の送信先、解析 SDK、外部フォント、HTTP サーバーは使用しません。インターネットに接続するのは、利用者がアップデートの確認・更新を押したときだけです。
- 設定や履歴はアンインストール後も残ります。バックアップする場合は Tempo をトレイから終了して、上記の保存先フォルダーをコピーしてください。

## 手元の Windows PC で負荷を測る

1. Tempo を起動し、ダッシュボードを閉じてトレイに常駐させます。
2. スタートメニューの「Tempo の負荷測定」を起動します。ZIP 版は同じフォルダーの `Measure-Tempo.exe` を起動します。通常どおり PC を使ってください。サイト計測の負荷を含める場合は、拡張機能を有効にした Chrome・Edge も操作します。
3. 120 秒の測定と年間容量試験が終わると、テキストの結果が開きます。保存先は `%LOCALAPPDATA%\Tempo\Measurements` です。結果に閲覧履歴は含まれず、外部への送信も行いません。

CPU は PC 全体と 1 論理コア換算の両方、メモリは常駐本体と同じインストール先の連携ホストの合計ワーキングセット（平均・ピーク、10 進 MB）を表示します。GPU は Windows の GPU Engine カウンターで、対象プロセスが使った最も忙しいエンジンの使用率とサンプル数を示します。取得できない項目には `unavailable` と表示します。GPU サンプルが一部しかない場合は取得できた区間の値です。

容量試験は別の一時 SQLite に 365 日 × 24 時間 × 16 組の記録、4,096 ドメイン、65 アプリの模擬メタデータを作り、ファイルのバイト数を測ります。利用者の履歴 DB は書き換えません。実際の履歴容量は、アプリ・ドメイン数や稼働時間で変わります。長時間の測定には `Measure-Tempo.exe --seconds 3600 --no-open` を使用できます。

## 開発と検証

- `native/recorder.cpp` が Win32 のメッセージループ、トレイ、計測を担当します。`native/browser.cpp` がブラウザ連携ホストです。どちらも CLR とブラウザエンジンをロードしません。
- `native/store.hpp` は Windows 標準の SQLite に保存します。1.1 以降はアプリとドメイン文字列を整数 ID に変換して時間帯テーブルを小さく保ちます。1.0 の履歴はそのまま残り、新規記録と一緒に集計できます。
- `Tempo.Dashboard.exe` は画面を開いた間だけ動く C# プロセスです。アイコンやファイル説明の取得もこのプロセスで行います。`src/Core` にレポート集計、`src/UI` に画面、`extension` にブラウザ拡張機能があります。
- 負荷測定は独立した `Measure-Tempo.exe` で実行します。性能カウンターや模擬データ生成は通常の常駐動作では使用しません。

再ビルドには .NET 8 SDK、Python 3、MinGW-w64 x64 の G++（C++17）、windres、dlltool、amd64-unicode を含む NSIS 3.11 以降を使います。クロスコンパイラの既定名は `x86_64-w64-mingw32-g++` です。Windows 上の MinGW-w64 で `g++`・`windres`・`dlltool` を使う場合は、環境変数 `CXX`・`WINDRES`・`DLLTOOL` にその名前を指定してください。初回ビルドは NuGet から固定バージョンの参照アセンブリと WebView2 SDK を取得します。

パスが長いフォルダーでは .NET Framework のビルドが MAX_PATH で失敗します。`subst` で短いドライブ名を割り当ててからビルドしてください。リリース時の署名と公開の手順は [RELEASE.md](RELEASE.md) にあります。

```powershell
python scripts/package.py
dotnet run --project tests/Tempo.Tests.csproj -c Release
node --test tests/extension.test.js
```

ネイティブの計測ロジックは C++17 で `tests/timeline.cpp` をビルドして試験できます。UI 試験は Python の Playwright（`pip install playwright==1.49.1`）と Microsoft Edge を使います。`python tests/dashboard.py` を実行してください。記録のあるデータと、初回起動（記録ゼロ）の両方を、ライト・ダーク・3 種類の幅・150%/200% DPI で確認します。`TEMPO_SCREENS=1` を設定すると、`docs/screens` に画面例を保存します。別の Chromium を使う場合は、環境変数 `CHROMIUM` に実行ファイルのパスを設定してください。

実測値と実機で残っている項目は [検証結果](VERIFICATION.md) に記載しています。
